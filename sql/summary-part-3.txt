

# 40. Trigger Syntax

```sql
DELIMITER //

CREATE TRIGGER check_salary
BEFORE INSERT
ON emp
FOR EACH ROW
BEGIN
    IF NEW.salary <= 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Salary must be greater than 0';
    END IF;
END //

DELIMITER ;
```

### Show triggers

```sql
SHOW TRIGGERS;
```

### Delete trigger

```sql
DROP TRIGGER check_salary;
```

# 41. STORED PROCEDURE

A **stored procedure** is a group of SQL statements stored in the database and executed when called.

### Create procedure

```sql
DELIMITER //

CREATE PROCEDURE show_employees()
BEGIN
    SELECT * FROM emp;
END //

DELIMITER ;
```

### Execute

```sql
CALL show_employees();
```

### Delete

```sql
DROP PROCEDURE show_employees;
```

### Procedure vs Trigger

```text
Procedure → Called manually
Trigger   → Executes automatically
```

# 46. TRANSACTIONS

A **transaction** is a group of SQL operations treated as one unit.

Main commands:

```text
COMMIT
ROLLBACK
SAVEPOINT
```

---

## COMMIT

Permanently saves changes.

```sql
COMMIT;
```

---

## ROLLBACK

Undo changes that haven't been committed.

```sql
ROLLBACK;
```

---

## SAVEPOINT

Creates a point to which you can roll back.

```sql
SAVEPOINT sp1;
```

Then:

```sql
ROLLBACK TO sp1;
```

# 48. NORMALIZATION

**Normalization** is the process of organizing data into related tables to reduce redundancy and improve data integrity.

Main goals:

```text
Reduce redundancy
Avoid anomalies
Improve consistency
Improve data integrity
```

---

# 49. ANOMALIES

Three important problems caused by poor database design:

### Insert Anomaly

Difficulty inserting data without unrelated data.

### Update Anomaly

Same data exists in multiple places and must be updated everywhere.

### Delete Anomaly

Deleting one piece of information accidentally removes another important piece of information.

---

# 50. 1NF

**First Normal Form**

Rules:

* Values must be atomic
* No multiple values in one cell
* No repeating groups

### Memory

```text
1NF = One value per cell
```

---

# 51. 2NF

**Second Normal Form**

Rules:

```text
2NF = 1NF + No Partial Dependency
```

Partial dependency occurs when a non-key attribute depends on only part of a composite primary key.

---

# 52. 3NF

**Third Normal Form**

Rules:

```text
3NF = 2NF + No Transitive Dependency
```

Transitive dependency:

```text
A → B
B → C

Therefore:
A → B → C
```

A non-key attribute should not depend indirectly on the primary key through another non-key attribute.

---

# 53. BCNF

**BCNF = Boyce-Codd Normal Form**

BCNF is a stronger version of 3NF.

Main rule:

> Every determinant must be a candidate key.

---

# 54. NORMALIZATION MEMORY TRICK

```text
1NF  → Atomic values
2NF  → No Partial Dependency
3NF  → No Transitive Dependency
BCNF → Every determinant is a Candidate Key
```

# 55. KEYS

Important keys in SQL:

```text
PRIMARY KEY
FOREIGN KEY
CANDIDATE KEY
COMPOSITE KEY
```

### Primary Key

Uniquely identifies each row.

### Foreign Key

Connects one table to another.

### Candidate Key

A column or combination of columns capable of uniquely identifying a row.

### Composite Key

A key made using multiple columns.

Example:

```sql
PRIMARY KEY (student_id, course_id)
```

# 56. MOST IMPORTANT SQL PATTERNS

## Simple filtering

```sql
SELECT *
FROM table_name
WHERE condition;
```

## Sorting

```sql
SELECT *
FROM table_name
ORDER BY column_name DESC;
```

## Grouping

```sql
SELECT column_name, COUNT(*)
FROM table_name
GROUP BY column_name;
```

## Grouping + condition

```sql
SELECT column_name, COUNT(*)
FROM table_name
GROUP BY column_name
HAVING COUNT(*) > 1;
```

## Grouping + sorting

```sql
SELECT column_name, AVG(price)
FROM table_name
GROUP BY column_name
ORDER BY AVG(price) DESC;
```

## Top N

```sql
SELECT *
FROM table_name
ORDER BY price DESC
LIMIT 3;
```

## Skip + take

```sql
SELECT *
FROM table_name
ORDER BY price DESC
LIMIT 3 OFFSET 2;
```

## JOIN

```sql
SELECT a.column, b.column
FROM table1 a
INNER JOIN table2 b
ON a.id = b.id;
```

# 58. WHERE vs HAVING

This is one of the most important concepts.

```text
WHERE
↓
Filters individual rows
↓
Before GROUP BY

HAVING
↓
Filters groups
↓
After GROUP BY
```

Example:

```sql
SELECT category, AVG(price) AS average_price
FROM product
WHERE quantity > 10
GROUP BY category
HAVING AVG(price) > 8000;
```

Here:

```text
WHERE quantity > 10
→ filters individual products

HAVING AVG(price) > 8000
→ filters categories
```

---

# 59. COUNT(*) vs COUNT(column)

```sql
COUNT(*)
```

Counts rows.

```sql
COUNT(column_name)
```

Counts non-NULL values in that column.

Example:

```sql
SELECT COUNT(*)
FROM emp;
```

versus:

```sql
SELECT COUNT(manager_id)
FROM emp;
```

The second doesn't count rows where `manager_id` is `NULL`.

This is particularly important with `LEFT JOIN`.
